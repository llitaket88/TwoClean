# TwoClear — Спецификация проекта

## Обзор

**TwoClear** — утилита для Windows, которая помогает навести порядок после работы с платформой 1С:Предприятие 8. Это порт проекта [OneCleaner](https://github.com/vbondarevsky/OneCleaner) (C# / WPF) на Rust с использованием GPUI и gpui-component.

**Название:** TwoClear (2Clear → Two → «Два» → 1С:Предприятие **2.0 очистки** 😄)

**Стек:** Rust 2024 edition, GPUI (из репозитория Zed), gpui-component 0.5+

**Платформа:** Windows only (x86_64)

---

## Функциональные требования

### Таб 1: Версии платформы

**Источник данных:** Windows Registry
- `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` (32-bit view)
- `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` (64-bit view, на 64-bit ОС)

**Критерий фильтрации:** значение `Publisher` должно быть одним из: `1С-Софт`, `1C-Soft`, `1C`, `1С`, а `InstallLocation` не должно быть пустым.

**Отображаемые поля:**
| Поле | Источник |
|------|---------|
| Название | `DisplayName` |
| Версия | `DisplayVersion` (e.g. `8.3.20.1710`) |
| Дата установки | `InstallDate` (yyyyMMdd → yyyy-MM-dd) |
| Размер | Размер директории `InstallLocation` |
| Чекбокс | Выбор для удаления |

**Сортировка:** по умолчанию по версии (от старой к новой).

**Операции:**
- Выбрать все / Снять выбор
- **Удалить выбранные** — запускает `msiexec.exe /x{UUID} /q` для каждой выбранной версии последовательно, с индикацией прогресса. После успешного удаления запись убирается из списка.

**Состояния:**
- Загрузка (spinner) пока идёт чтение реестра и подсчёт размеров
- Индикатор прогресса при удалении (`X из N`)
- Кнопка "Отмена" во время удаления

---

### Таб 2: Кэш метаданных

**Источник данных:** Файловая система
- Базовый путь: `%LOCALAPPDATA%\1C`
- Перебирать директории, соответствующие паттерну `1cv8*`
- Внутри каждой — поддиректории, имя которых является UUID: `[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}`

**Отображаемые поля:**
| Поле | Источник |
|------|---------|
| Название базы | Найденное имя из `ibases.v8i` по UUID, или `<База не найдена>` |
| UUID | Имя директории |
| Размер | Размер директории (рекурсивно) |
| Чекбокс | Выбор для удаления |

**Логика выбора по умолчанию:**
- Записи, для которых не найдена соответствующая информационная база: `selected = true` (orphaned cache — смело чистить)
- Записи с найденной базой: `selected = false`

**Операции:**
- Выбрать все / Снять выбор / Выбрать осиротевшие
- **Удалить выбранные** — удаляет директории кэша

---

### Таб 3: Информационные базы

**Источник данных:** Файл `%APPDATA%\1C\1CEStart\ibases.v8i`

Это INI-подобный файл следующего формата:
```
[Имя базы]
Connect=File="C:\1c\base";
ID={GUID}
DefaultVersion=8.3.20

[Серверная база]
Connect=Srvr="server";Ref="basename";
ID={GUID}
Version=8.3.19
```

**Отображаемые поля:**
| Поле | Источник |
|------|---------|
| Название | Имя секции `[...]` |
| Версия | `DefaultVersion` или `Version` |
| Тип | Файловая / Серверная (определяется по `Connect`) |
| Путь / Сервер | Из `Connect` |
| Размер | Для файловых баз — размер директории, для серверных — 0 |
| Чекбокс | Выбор для удаления |

**Операции:**
- Выбрать все / Снять выбор
- **Удалить выбранные** — для каждой выбранной базы:
  1. Если файловая база (`Connect` начинается с `File=`) И путь локальный (не UNC `\\`): удалить директорию базы
  2. Удалить запись из `ibases.v8i`
  3. **Перед изменением файла:** создать резервную копию `ibases.v8i_backup_{timestamp}` в той же директории

## Нефункциональные требования

### Производительность
- Загрузка данных и подсчёт размеров директорий должны выполняться в фоне (`background_executor`), не блокируя UI
- Таблицы с большим числом записей (сотни) должны отображаться без задержек (GPUI рендерит всё в GPU)

### Надёжность
- Деструктивные операции (удаление) должны быть подтверждены диалогом
- Обязательное создание бэкапа `ibases.v8i` перед изменением
- Ошибки при удалении отдельных записей не должны прерывать операцию для остальных — они логируются и показываются пользователю
- Флаг `operation_in_progress` предотвращает двойное выполнение операции

### Интерфейс
- Тёмная тема по умолчанию
- Вкладки в заголовке окна (в стиле `system_monitor` примера)
- Показ суммарного размера выбранных и всех элементов в тулбаре каждой вкладки
- Строка статуса внизу окна: текущее состояние, ошибки
- Кнопка обновления (reload) на каждой вкладке
- Плавная анимация чекбоксов (встроена в gpui-component)

### Окно
- Размер: 900×640 px, по центру экрана
- Заголовок: "TwoClear — Очистка 1С"
- Минимальный размер: 700×500 px

## Архитектура

```
┌─────────────────────────────────────────────────────────┐
│                      main.rs                            │
│   gpui_platform::application() + window setup           │
└────────────────────────┬────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────┐
│                      app.rs                             │
│   TwoClearApp { versions, cache_entries, infobases, ... }│
│   impl Render → tabs + toolbar + list                    │
└────────────────────────┬────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────┐
│                   platform/                              │
│  versions.rs  ←  Windows Registry (winreg)              │
│  cache.rs     ←  %LOCALAPPDATA%\1C\ (std::fs)           │
│  infobases.rs ←  ibases.v8i (custom INI parser)         │
│  utils.rs     ←  get_dir_size (walkdir), format_size    │
└─────────────────────────────────────────────────────────┘
```

### Модуль `platform`

Все функции синхронные, возвращают `anyhow::Result<T>`. Вызываются через `cx.background_executor().spawn()` чтобы не блокировать UI.

```rust
// Версии
pub fn get_installed_versions() -> Result<Vec<InstalledVersion>>
pub fn uninstall_version(uuid: &str) -> Result<bool>

// Кэш
pub fn get_cache_entries() -> Result<Vec<CacheEntry>>
pub fn delete_cache_entries(paths: &[String]) -> Result<()>

// Информационные базы
pub fn get_info_bases() -> Result<Vec<InfoBase>>
pub fn delete_info_bases(names: &[String]) -> Result<()>
```

### Модуль `app`

Центральный `TwoClearApp` struct хранит всё состояние. Render-методы разбиты по смыслу:
- `render_title_bar()` — вкладки
- `render_versions_tab()` → `render_versions_toolbar()` + `render_versions_list()`
- `render_cache_tab()` → аналогично
- `render_infobases_tab()` → аналогично
- `render_status_bar()` — нижняя строка состояния

## Вне скоупа (Out of Scope)

- Поиск/фильтрация по имени внутри вкладок
- Настройки приложения
- Автоматическая очистка по расписанию
- Поддержка macOS/Linux
- Удалённые базы (серверные базы не удаляются физически — только из списка)
- Логирование в файл
